# 示例报告

这个目录里的报告**全部由 [`samples/`](../samples) 下的合成数据生成**，
不是任何人的真实聊天记录。可以直接双击打开看效果。

| 文件 | 对应数据 | 分数与结论 |
|---|---|---|
| [`report-cooling.html`](report-cooling.html) | `demo_two_block_cooling.txt`（从热到冷的 203 天） | **58 / 100 · 有点平淡了** |
| [`report-warm.html`](report-warm.html) | `demo_two_block_warm.txt`（互相都在投入的 29 天） | 64 / 100 · 有点平淡了（样本偏少，已收缩） |
| [`report-too-short.html`](report-too-short.html) | `demo_too_short.txt`（只有 5 条消息） | **样本不足，无法给结论**——8 个维度全部标 N/A |
| `report-cooling.json` | 机器可读的完整结果 | 维度分、权重、贡献、分段趋势、证据、话题、画像、时间线 |

## 最值得看的两份

**`report-cooling.html`** —— 完整示例。一眼就能看出这条叙事线：
回复速度还行、但称呼在消失、收尾全是他、情绪在变冷。

**`report-too-short.html`** —— 展示产品里最重要的一道闸门：
样本不够时**明确说不知道**，而不是编一个数字。

## 看报告时建议留意这几处

报告是**一页一页往下翻**的（左侧导航共 14 页，滚轮或方向键翻页，
每页右上角有页码）：

1. **第 1 页 结论**：环形仪表盘、等级大字、一句话结论，以及「这个分数有多可信？」。
   样本不足时这里会先出现一条黄色横幅——那是设计里最重要的一道闸门。
2. **第 2 页 量化指标**：每项都附**计算口径与数据来源**，可以自己复核。
3. **第 5 / 6 / 7 页**：日历热力图、词云、行为画像，颜色与字号都有明确编码，
   图下方写了口径。
4. **第 10 页 维度明细**：样本不足的维度标 `N/A`，并明确写出「这一项没有参与打分」，
   **不会被当成 0 分**。
5. **第 12 页 原话与证据**：每一句都来自文件，未改写。自己复核比相信分数更重要。
6. **第 13 页 分数是怎么算出来的**：完整的权重与贡献分账，
   可以逐条追问「这 58 分怎么来的」。
7. **最后一页**：分档安慰文案 + 一句从这份记录里长出来的个性化文案。

## 自己重新生成

```bash
python -m loves_me_not analyze "samples/demo_two_block_cooling.txt" \
    --me "我" --peer "阿澈" \
    -o demo/report-cooling.html --json demo/report-cooling.json
```

想试脱敏：给命令加上 `--redact`。
合成数据里没有手机号之类的串，所以输出内容与不加时一致；
换成你自己的记录就会看到打码效果。

## 关于示例数据

`samples/` 里是**手写合成的**对话，用于覆盖各种格式与边界情况：

| 文件 | 覆盖的形态 |
|---|---|
| `demo_two_block_warm.txt` | 两行式时间戳；双方都主动、有深夜消息、有亲昵称呼 |
| `demo_two_block_cooling.txt` | 同样的格式，但逐步降温（回复变慢、称呼消失、单方面推进） |
| `demo_paste_oneline.txt` | 单行粘贴式（`昵称  日期 时间`），含一条撤回系统消息 |
| `demo_table.csv` | 表格格式（`localId,Time,Sender,Content`） |
| `demo_too_short.txt` | 只有 5 条消息，用来验证「样本不足时必须明确提示，不得虚构结论」 |

**这些不是真实记录。** 想分析自己的聊天记录，请按
[README](../README.md#-使用) 里的说明导出后本地运行。
