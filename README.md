# 🌼 loves-me-not —— TA 到底爱不爱我

> 撕开聊天记录的花瓣，看看 TA 爱不爱你。
>
> 导入微信 / QQ 导出的纯文本聊天记录，在**本机**算出一个 0–100 的「情感投入指数」，
> 生成一份可以直接发小红书的**单文件 HTML 可视化报告**。

---

## ⚠️ 先读这一段：这是什么，这不是什么

| | |
|---|---|
| **它是** | 一个「娱乐 + 自我反思」工具。用统计学规律把你已经感觉到的相处模式，画成看得见的图。 |
| **它不是** | 关系裁判，也不是读心术。它不知道对方在想什么，它只数得清谁先开口、谁回得快、谁在收尾。 |
| **它是** | 全本地运行。聊天记录不出你的设备，不上传、不联网、不调用任何云端 AI。 |
| **它不是** | 微信数据库解密工具。见下方「法律与隐私红线」。 |

> 本报告基于统计学规律生成，仅供娱乐与自我反思，不代表任何一方的真实情感，
> 重大情感决策请咨询线下专业人士。

**分数低不等于他不爱你，分数高也不等于你们会一直在一起。**
一段关系里的沉默，可能是冷淡，也可能是他那天加班到十一点、手机没电、或者他本来就不太会说话。
工具只能看见文字，看不见人。

## 🚨 法律与隐私红线（请务必读完）

**1. 本项目不读取微信数据库，不绕过微信安全机制。**
它只接受**你自己用导出工具导出的文本/CSV 文件**（例如留痕 MemoTrace 的导出结果）。
微信官方已明确打击通过代码注入或提示词注入获取聊天记录的行为——本项目**不内置**、也**永不会内置**任何解密微信数据库的功能。

**2. 聊天记录涉及双方的隐私。**
用量分析别人的聊天记录，本身是有伦理灰度的事。请确认：

- 你已获得对话参与者的授权，或这些记录是你自己的；
- 你只在本地处理，不把原始记录上传到任何网盘 / 在线服务 / 公开 demo；
- 不要用它去跟踪、监视、控制任何人。

**3. 默认全本地。**
`data/` 与 `out/` 已在 `.gitignore` 中，你的真实聊天记录不会被提交进版本库。
解析、计算、绘图全部在本机内存中完成，**运行过程中没有任何网络请求**。

## 🚀 快速开始

无需安装任何第三方依赖，只需要 Python 3.9+（纯标准库实现）。

```bash
# 1. 先核对解析结果（强烈建议：输入错了，分数就没有意义）
python -m loves_me_not inspect "path/to/chat.txt"

# 2. 分析并生成报告
python -m loves_me_not analyze "path/to/chat.txt" --me "我的昵称" --peer "TA的昵称" \
    -o out/report.html --json out/result.json

# 3. 要把报告发给别人看时，先打码
python -m loves_me_not analyze "path/to/chat.txt" --me "我" --peer "TA" --redact -o out/report.html
```

`analyze` 会打印分数、等级、可信度，以及在控制台里列出所有数据说明；
报告写到 `-o` 指定的路径（默认 `out/report.html`）。

**参数一览**

| 参数 | 说明 |
|---|---|
| `--me` | 「我」的昵称。**不指定时会按说话人出现顺序推断，并在报告顶部警告你核对**——搞反了整份结论会颠倒。 |
| `--peer` | 「TA」的昵称。记录里有 3 个以上说话人（群聊）时建议指定。 |
| `-o, --output` | 报告输出路径，默认 `out/report.html`。 |
| `--json` | 额外输出机器可读的完整结果（维度分、权重、贡献、分段趋势、证据）。 |
| `--redact` | 对报告中的手机号、身份证、卡号、邮箱、账号、地址做打码。 |
| `--format` | `auto`（默认）/ `text` / `csv`，强制指定输入格式。 |

**退出码**：`0` 成功；`2` 表示解析失败或参数有误（例如文件不是聊天记录导出、
找不到你指定的说话人、记录里没有任何有效消息）。**失败时不会生成任何报告**，
更不会编一份出来。

Windows 上如果 `python` 不可用，试 `py -m loves_me_not ...`。

**只想看看它长什么样？** `demo/` 里有用合成数据生成的示例报告，双击就能打开。

## 📥 支持的输入格式

### 微信（推荐：留痕 MemoTrace 导出的 CSV）

留痕导出的 CSV 通常长这样（列名顺序可能不同，本项目按列名模糊匹配）：

```csv
localId,Time,Sender,Content
1,2023-04-01 21:33:02,阿澈,到家了跟我说一声
2,2023-04-01 21:35:11,我,到啦
```

也支持中文表头 / 无表头：

```csv
时间,发送者,内容
2023-04-01 21:33:02,阿澈,到家了跟我说一声
```

### 微信 / QQ 文本导出（txt / log）

```text
2023-04-01 21:33:02 阿澈
到家了跟我说一声

2023-04-01 21:35:11 我
到啦
```

微信 PC 端直接「复制」出来的 `昵称  日期 时间` 格式也直接支持：

```text
阿澈  2023/11/05 22:14:03
今天加班到好晚

我  2023/11/05 22:15:10
辛苦啦 吃饭了吗
```

```text
2023-04-01 21:33:02 阿澈(12345678)
到家了跟我说一声
```

QQ 导出常见的方括号格式也支持：

```text
[2023-04-01 21:33:02] 阿澈
到家了跟我说一声
```

### 解析器会容错处理

- **多种时间戳**：`2023-04-01 21:33:02`、`2023/4/1 21:33`、`2023年4月1日 21:33`、`[21:33:02]`（无日期时按顺序推断日期）、时间戳与昵称在任意一侧
- **多行消息**：昵称行之后的连续行自动并入同一条消息
- **系统消息**：`撤回了一条消息`、`加入了群聊`、`[图片]`、`[表情]` 等自动识别并单独标记（不计入字数统计）
- **群聊**：说话人超过两个时自动降级为「取你与互动最多的那个人」，并在报告中提示
- **BOM / GBK / UTF-8**：自动探测编码，不会因为编码问题整份文件读不出来

> 解析完建议先跑一次 `inspect` 子命令，确认说话人识别无误再看分数——**输入错了，分数就毫无意义**。

## 📊 八个分析维度

所有维度都以**双方对比**的方式呈现：差距（不对称性）往往比绝对值更能说明问题。

| 维度 | 怎么算 | 心理含义 |
|---|---|---|
| **回复间隔与响应速度** | 每次回复相对上一条对方消息的间隔；取中位数与均值、5 分钟内回复率、超过 1 小时才回的比例 | 谁在秒回，谁总在「稍后」 |
| **主动发起对话次数** | 每日首条消息归属 + 静默 ≥6 小时后的「冷启动」由谁开启 + 连续消息段归属 | 谁更在意这段关系 |
| **平均字数** | 每条消息字符数、长短消息比例；同时给「实质性消息」（≥6 字、非纯表情）口径，避免被「嗯」「哈哈」拉平 | 一方是否在敷衍 |
| **提问与追问比例** | 含疑问词或问号的消息占比 + 提问后 10 分钟内继续追问的比例 | 是「想了解你」还是「懒得接话」 |
| **称呼与表情使用** | 亲昵称呼（宝宝/亲爱的/老婆…）词频、表情与表情包占比、称呼随时间的变化趋势 | 关系温度的语言痕迹 |
| **谁在结束对话** | 谁发出最后一条消息后对话结束、谁在对方提问后「不接话」直接离开 | 谁先转身 |
| **深夜及特定时段活跃度** | 23:00–03:00 消息占比、双方各自的活跃时段分布 | 情感浓度（好或坏都算） |
| **情绪倾向随时间变化** | 基于情感词典的逐条极性打分，按时间分段看均分与趋势方向 | 是越来越甜，还是越来越客气 |

**情感词典是本地的、可审计的**（见 `loves_me_not/lexicon.py`），不依赖任何在线模型。
它不完美——反讽、网络梗、方言都会误判。所以报告里每一个结论都附上**原始聊天片段**，让你自己复核。

## 🧮 打分模型（可解释，不黑箱）

- 每个维度先算出若干**子指标**，各自映射到 0–100；子指标加权得到维度分，维度分再加权得到总分。
- **权重随「TA 视角 / 我的视角」切换**：判断「TA 爱不爱我」时，看的是 TA 的回复速度、TA 的主动性、TA 的投入度。
- **样本不足会降级而不是猜**：
  - 样本量低于阈值 → 总分区间收窄，报告顶部直接标注**「样本不足」**并拒绝给强结论；
  - 某个维度无法计算（例如全程没出现过任何亲昵称呼）→ 该维度标记为 `N/A` 并从加权中剔除，权重重新归一化，**绝不当成 0 分**；
  - 聊天记录里没有任何内容 → 直接报错退出，**不生成任何虚构报告**。
- 所有中间量都会写进报告和 JSON，你可以逐条追问「这 47 分是怎么来的」。

**等级结论**

| 分数 | 等级 | 说明 |
|---|---|---|
| 85–100 | 还是很爱你 | 主动、秒回、话题不断 |
| 70–84 | 热度在线 | 整体稳定，偶有降温 |
| 55–69 | 有点平淡了 | 还在，但节奏放慢了 |
| 40–54 | 已经在变淡 | 多项指标偏向单方面 |
| 20–39 | 基本没戏 | 长期单方面投入，回应稀薄 |
| 0–19 | 几乎可以放手了 | 数据上看这段关系已经停摆 |

## 🧭 五个量化指标（只看 TA 的行为信号）

除了上面覆盖面较广的八维模型，报告里还有一组更聚焦的量化指标，
专门回答「TA 在这段关系里的投入信号有多强」。**每一项的计算口径与数据来源
都会原样印在报告里**，可以自己复核。

| 指标 | 计算口径 | 数据来源 | 展示形式 |
|---|---|---|---|
| **回复速度** | TA 每次回复与上一条对方消息的时间差（只统计 ≤24 小时的间隔），取**中位数**；映射曲线 5 分钟 ≈ 50 分，越快越高 | 每条消息的时间戳与说话人 | 中位时长 + 5 分钟内回复率 + 均值 |
| **每 5 分钟发消息次数** | 把 TA 的消息按 5 分钟窗口分桶，取**有消息的窗口**的平均条数（= 连续说话时的密度），另给单窗口峰值 | 消息时间戳 | 平均条数 / 5 分钟 + 峰值时刻 |
| **深夜发消息次数** | TA 在 **23:00–03:00** 发出的消息条数，并换算成占 TA 总量的比例（20% ≈ 100 分） | 消息时间戳小时数 | 条数 + 占 TA 全部消息的比例 |
| **打破僵局次数** | 沉默 **≥24 小时**后，下一段对话的第一条消息由谁发出；统计 TA 破冰次数 ÷ 总破冰次数 | 会话分段（30 分钟无消息即断开）+ 时间戳 | 「TA 破冰 / 总次数」+ 最长一次沉默由谁打破 |
| **最后发言次数** | 每段对话最后一条消息的归属；TA 占 **50% 最均衡**，越偏离 50%（无论谁多）说明收尾越固定在一方 | 会话分段 + 说话人 | 「TA 收尾 / 总段数」+ 收尾占比 |

**综合情感倾向** = 五项各自映射到 0–100 后加权：

```text
回复速度 30% + 打破僵局 25% + 最后发言 20% + 每5分钟条数 15% + 深夜 10%
```

> 深夜权重刻意最低——凌晨消息多可能是关心，也可能只是作息晚，
> 它是「情感浓度」的信号，而不是「投入」的信号。
>
> 「打破僵局」和「最后发言」**没有绝对好坏**：双方各半最健康，
> 全由一方承担会降低得分。这一点和「越主动越好」的直觉不一样，是有意为之。

**总分是两个视角的综合**：八维模型（权重 60%，覆盖面广）+ 五项量化指标（权重 40%，聚焦行为信号）。
任何一方样本不足时就用另一方，**绝不把缺失方当 0 分**；综合之后再按样本量做收缩。

## 📍 聊天足迹与关键节点

报告会算出这些「描述性」结论（不参与打分，但往往是用户最想看的）：

| 指标 | 口径 |
|---|---|
| **聊天跨度** | 第一条消息 → **今天**的天数；另外给出首尾消息之间的跨度 |
| **聊得最好的时段** | 24 小时分布里**连续三小时**消息量最高的那一段 |
| **聊得最多的月份** | 按月统计消息条数取最大者，同时标出最安静的月份 |
| **互动最均衡的月份** | 消息量不低于最高月 25% 的月份里，TA 发言占比最高者（**代理指标**，不是感情真相） |
| **累计聊天时长** | 各段对话（相邻消息间隔 ≤30 分钟）时长之和 |
| **最长的一次聊天** | 单段对话时长最长者，含起止时刻与消息数 |
| **最长的一次沉默** | 两个会话之间最长的空档，以及最后由谁打破 |
| **聊得最多的一天 / 聊得最久的一天** | 按消息条数 / 按各段对话时长之和 |
| **关键节点时间线** | 第一次与最后一次说话、最长一次聊天、最长沉默、最热闹与最久的一天、最多与最安静的月份、最暖与最冷的一天、**热度转折点** |

热点转折点用**居中窗口**比较前后两个月的平均消息量，并要求两侧都有实质活动量
（各 ≥4 条消息、变化 ≥50%），否则「从 3 条涨到 12 条」这种噪声也会被标成转折点。

## 📄 报告长什么样

单文件 HTML，双击即开，没有任何外部依赖（不联网、不加载 CDN），手机上也排得下：

1. **顶部大字直白给结论** —— 一眼看到分数和等级，不用翻
2. **五个量化指标** —— 每项都写明口径与来源，附权重与贡献
3. **得分仪表盘 + 双方投入度对比**
4. **关键数据卡片**
5. **聊天足迹** —— 跨度、时段、月度、最长一次、最长沉默
6. **聊天日历热力图**
7. **话题词云**
8. **「TA 是一个怎样的人」行为画像**
9. **关键节点时间线**
10. **八维雷达图** —— 哪几项拖了后腿，一眼看出
11. **维度明细** —— 每个维度的子指标数据块
12. **互动趋势四张折线图** —— 消息量 / 主动发起 / 情感倾向 / 回复速度
13. **主要加分项与拖后腿项**
14. **典型原话摘录** —— 支撑结论的**真实片段**，自己复核
15. **完整分数分账** —— 八维权重 + 量化权重 + 综合方式
16. **温柔克制的收尾** —— 承认人心会变，鼓励你向前看，不说教、不指责
17. **固定的数据来源与免责声明**

JSON 输出（`--json`）包含以上全部数据：量化指标、足迹（含每一天）、时间线、
话题、画像、分段趋势与证据，方便二次开发。

## 🧪 测试

```bash
python -m unittest discover -s tests -v
```

测试里有几条是**守住产品承诺的护栏**，改动核心逻辑时不要删：

- 无信息的维度必须被剔除，而不是当成 0 分（含「表情线索不可得」的情形）
- 样本不足必须降级为「样本不足」，不得输出强结论
- 采样不足的量化指标 `score` 必须是 `None`，不能是 `0.0`
- 更暖的记录必须得到更高的分（打分方向不能反）

- 「谁收尾」「谁破冰」必须是对称的：50% 满分，两端更低
